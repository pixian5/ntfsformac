## 一、报错弹窗：NSAlert → 自定义 NSPanel

### 旧实现（有问题）

```swift
private func alert(_ title: String, _ text: String) {
    let a = NSAlert()
    a.messageText = title
    a.informativeText = text     // 纯 label，不能选中
    a.alertStyle = .warning
    a.runModal()                 // 独占事件循环
}
```

三个具体毛病：

1. **文字不能选中**：`informativeText` 是普通 `NSTextField` label，无法拖选，长报错（含路径、设备名、hex）只能靠人眼抄，没法复制去搜索。
2. **`runModal()` 独占事件循环**：弹窗期间该 App 完全卡死（定时器停摆、菜单无法刷新），必须点掉才能继续。对菜单栏常驻 App 尤其糟糕。
3. **默认浮在最前抢焦点**：NSAlert 会 activate App 并把窗口提到最前，挡住用户正在操作的其它窗口。

### 新实现（`ErrorPanel`）

新建独立类 `ErrorPanel: NSObject, NSWindowDelegate`，要点：

| 需求 | 实现手段 | 说明 |
|---|---|---|
| 不置顶 | `panel.level = .normal` + `isFloatingPanel = false` | 普通窗口层级，不参与「始终置顶」；App 失活也不自动隐藏（`hidesOnDeactivate = false`） |
| 不抢焦点、不阻塞 | `orderFrontRegardless()` + `.nonactivatingPanel` + `becomesKeyOnlyIfNeeded = true` | 只把窗口提到前面，**不 activate App**，不抢键盘焦点；不调用 `runModal()`，事件循环照常跑 |
| 文字可选中 | `NSTextView`（`isSelectable = true`、`isEditable = false`）包在 `NSScrollView` 里 | 可直接拖选，⌘C 复制选段；等宽字体便于核对路径/设备名 |
| 复制按钮 | 「复制全部」按钮 → `NSPasteboard.general.setString(body)` | 整段报错一键入剪贴板；按钮文案短暂变「已复制 ✓」给出反馈（面板不是 key window，发不出声音提示） |
| 关闭 | 「关闭」按钮 + `Esc` 键（`keyEquivalent = "\u{1b}"`） | |
| 同错不叠加 | `errorPanels: [String: ErrorPanel]`，key = title + "\u{1}" + text | 自动解锁失败这类可能反复触发的错误，已开着就不再叠一层 |
| 多错错位 | `ErrorPanel.shown % 6` 递增平移 26pt | 多个报错同时存在时不完全重叠，用户能察觉有几个 |
| 内存 | `isReleasedWhenClosed = false` + `windowWillClose` → `onClose` 回调移除字典引用 | ARC 管理，避免关闭后野指针崩溃 |

另外 `alert()` 现在会把标题与正文写进 `~/Library/Logs/NTFSFormac/app.log`，便于事后排查（正文换行替换为 `⏎` 保持单行）。

## 二、`eject_one` 纳入互斥锁

`eject_one` 会做四件重活：解挂 FUSE-T 挂载、SIGTERM/SIGKILL 掉该设备的 `ntfs-3g` 进程、拆 `dislocker-fuse` 容器、最后 `diskutil eject` 父盘。

这些动作与「挂载 / 解锁 / 锁定」并发时会互相踩：典型后果是刚 eject 完的盘又被守护进程挂回来，或 dislocker 容器处于半拆状态导致下次解锁失败。

修复：函数入口即持锁，并注册 `EXIT` 兜底释放：

```bash
lock_mount || die "另一个挂载/卸载操作进行中，请稍后再试"
trap 'unlock_mount' EXIT
...
unlock_mount; trap - EXIT
```

至此 `mount_one` / `bl_unlock_one` / `bl_lock_one` / `eject_one` 四者对同一设备的状态变更全部串行化，互斥锁缺口清零。

## 三、手动锁定标记（`locked.<dev>`）

### 问题

菜单栏 App 每 3 秒轮询一次，看到 `state == locked` 的 BitLocker 卷且钥匙串里有凭据，就自动解锁。于是命令行 `ntfsctl lock disk4s1` 会被 App 在几秒内悄悄解开 —— **锁不住**，命令行的语义与 App 的自动化直接冲突。

### 设计

`bl_lock_one` 落下 `/var/run/ntfsformac/locked.<dev>` 标记；App 在自动解锁前检查该标记，存在则跳过。

标记的目录权限是 `0755 root:daemon`、标记文件默认 `0644`，**App 以普通用户身份即可 stat 到**，无需提权。实测 `FileManager.default.fileExists(atPath:)` 返回 `true`。

清理策略（三条互补，避免标记永久挡住自动解锁）：

| 时机 | 触发者 | 说明 |
|---|---|---|
| `ntfsctl unlock`（成功或发现已解锁） | CLI / App 解锁 | 用户主动解锁 = 撤销「保持锁定」意图 |
| `ntfsctl eject` | CLI / App 弹出 | 盘要走了，顺手清掉 |
| 设备节点消失（拔盘）或超 24h | `ntfsctl list` 内嵌的 `prune_locked_markers` | 关键：解决「拔盘再插回、盘号没变」时旧标记挡路 |

`prune_locked_markers` 挂在 `list` 分支里执行 —— App 每 3 秒以 root 调一次 `list`，是现成的心跳点，因此**不依赖守护进程是否存活**。它把日志写 stderr（`list --porcelain` 的 stdout 必须纯净，混进日志会打乱解析）。

App 侧：

```swift
for d in disks where d.fs == "bitlocker" && d.state == "locked" {
    if isManuallyLocked(d) { ...; continue }   // 尊重手动锁定意图
    ...
}
```

菜单里也会明示：手动锁定的盘显示 `[○ 加密·已手动锁定]`，并加一行「已手动锁定：不会自动解锁（解锁后即恢复）」；未解锁时的菜单项从「重新锁定 BitLocker」改为「锁定 BitLocker（锁定后不再自动解锁）」。

### 【关键修正】标记必须先落，再卸载

第一版把 `touch locked.$dev` 放在 `bl_close_container` **之后**，验证时撞上竞态：

```
lock 命令执行中 ──── 卷已 unmount，marker 尚未创建 ────▶ App 轮询到 locked、看不到 marker ─┐
                        （竞态窗口，数秒）                                                  │
                                                                                          ▼
                                                          App 自动解锁 → 调用 ntfsctl unlock → 清掉 marker
```

实测日志：`00:38:35 找到凭据 … 尝试自动解锁` → `00:38:43 自动解锁成功`，而 `ls` 显示 marker 是 `00:38` 创建的 —— 命令返回时 marker 已在，但 App 早在那之前就 refresh 过了。

修正：把 marker 创建提到 `lock_mount` 之后、任何卸载动作之前。这样两种情况都拦得住：

- refresh 早于本命令 → 看到的是 `rw`，根本不进自动解锁分支；
- refresh 晚于本命令 → 看到 marker，直接跳过。

修正后重测：**12 秒内卷保持 `locked`，App 日志零新增**（连 `readCredential` 都没有调用，说明 marker 检查在最前面就拦住了）。

## 四、顺带发现并修复：守护进程 porcelain 解析（影响面修正）

排查时注意到自动挂载守护进程（`ntfs-automount.sh`）的扫描循环：

```bash
"$NTFSCTL" list --porcelain | while IFS='|' read -r dev label fs mp state; do
  case "$state" in
    rw) ... ;;
    ro|none) ... ;;
  esac
done
```

v0.0.12 给 porcelain 加了第 6 个字段 `guid` 之后，`read` 只声明了 5 个变量，而 `read` 的最后一个变量会**吞下「本行剩余全部（含分隔符）」**。修复：补读第 6 字段并加 `_rest` 兜底（以后再加字段也不会重演）：

```bash
while IFS='|' read -r dev label fs mp state guid _rest; do
```

### 【重要修正】影响面比最初判断的小得多 —— 曾被自己的实测方法误导

最初我用交互 shell 复现，得到 `state="ro|"`，据此在文档与代码注释里写了「`ro`/`none` 的自动挂载**彻底静默失效**」。**这个结论是错的**，原因是：**我的复现是在 zsh 里跑的，而守护进程是 bash**，两者对「行尾空字段」的处理不同。

实测对照（输入 `disk26s1|AUTOTEST|ntfs|/Volumes/AUTOTEST|ro|`）：

| shell | 5 字段 `read` 得到的 `state` | 结论 |
|---|---|---|
| **bash 3.2**（守护进程实际使用的） | `ro`（**尾部空字段连同分隔符一起被剥掉**） | NTFS 卷不受影响 |
| zsh（我最初的复现环境） | `ro|` | 与 bash 结论相反，误导排查 |

而第 6 字段**非空**时（BitLocker 卷，guid 非空），两种 shell 一致：

| 输入 | 5 字段 `read` 得到的 `state` |
|---|---|
| `disk4s1\|Ventoy15.1\|bitlocker\|/Volumes/Ventoy15.1\|rw\|4967D63B-…` | `rw|4967D63B-…` ← **被污染** |

**所以真实影响面是**：

- **NTFS 卷（guid 为空）不受影响** —— bash 剥掉尾部空字段，`state` 仍是干净的 `ro`/`none`，自动挂载一直是好的。
  （这也正好解释了 v0.0.13 的 `test-automount` 为什么报 7/0 全绿：它测的正是 NTFS 路径，本来就没坏。）
- **BitLocker 卷（guid 非空）受影响** —— `state` 变成 `rw|4967D63B-…`，`case` 失配，导致：`rw` 分支的**只读寄生虫清理**不执行、`ro`/`none` 时**不自动挂载**。而 BitLocker 的实际挂载通常紧跟 unlock 由 App/CLI 直接完成，所以这一路的影响较隐蔽。

**决定性的实验**：我把守护脚本临时改回 5 字段并重装（核对 PID 确实换新、磁盘文件确为 5 字段），跑 `test-automount` —— **仍然 7/0 通过**，且守护日志打印的是干净的 `state=ro`。这就反证了「NTFS 路径未受影响」。实验后已立即恢复 6 字段版本并重新安装。

> 教训一：**跨 shell 的差异会伪造证据**。macOS 上交互 shell 是 zsh、脚本 shebang 是 bash（3.2），
> 两者对 `read` 行尾空字段的处理不同；任何 `read`/`IFS`/参数展开的复现都必须在 `/bin/bash` 下做，
> 否则会得出与运行时相反的结论（本次就先写出了一版错误的根因文档）。
> 教训二：**行式协议的字段数一旦变化，必须检查所有消费方**，且「多出的字段用兜底变量接住」应成为书写习惯。这类回归不报错、不写日志，只表现为功能莫名不工作。

## 五、bash 坑复发：`$var` 紧跟多字节字符

新写的日志行：

```bash
log "已锁定: /dev/$dev（不会被自动解锁；用 ntfsctl unlock $dev 恢复）"
```

输出成了 `已锁定: /dev/��不会再被自动解锁` —— `$dev` 被紧随其后的全角左括号 `（`（多字节 UTF-8 字符）当成变量名的一部分吞掉了。这是本项目第二次踩同一个坑（见 known-issues #38）。

修复：`${dev}（`。**规则：bash 里变量后面只要不是 ASCII 分隔符，一律写 `${var}` 定界。**

## 后续可选优化

1. **App 自动解锁与守护进程自动挂载的其它竞态**：`ejecting.<dev>`（60s 挂起）与 `locked.<dev>`（手动锁定）是两套独立标记，语义有重叠。可考虑合并成一个带「原因码」的标记（`reason=eject|lock`），减少状态组合。
2. **`locked.<dev>` 用设备名做键**：与钥匙串用卷 GUID 不同，标记只能按设备名（因为设备消失即失效，恰好是想要的语义）。但若用户在锁定后拔盘插到同一盘号且未触发 prune（`list` 未被调用），标记会残留 —— 目前靠 TTL 24h 兜底。可考虑在 `list` 里比对「设备节点 inode/创建时间」增强判定。
3. **ErrorPanel 增加「保存到文件」按钮**：超长报错（如 dislocker `-vv` 全量日志）复制到剪贴板再粘贴仍不便，直接落盘更实用。
4. **`test-manual-lock.sh` 补真实盘用例**：目前真实盘验证在对话中手工完成；可把「lock → 观察 → unlock」写成脚本，但需要凭据（钥匙串在用户身份下，root 读不到），可改为以用户身份调用 `ntfsctl unlock`。
