# 其它分区检测 + 只读裸镜像挂载 + 根除指纹弹窗（v0.0.15）

> 模型：DeepSeek-V4.1-Flash　时间：2026-10-15 07:45　版本：v0.0.14 → v0.0.15

## 需求来源

用户原话：

> 「我的优盘有多个分区，现在另一个没加密的分区没检测到」
> 「你想办法避免我老用指纹验证，你在测试什么？怎么老是弹出指纹验证」

拆成两件事：① 让「其它分区」能被检测并可浏览；② 根除一切 Touch ID 指纹弹窗。

---

## 一、问题定位：为什么 VTOYEFI 分区「没检测到」

U 盘（disk25，16.4GB，Ventoy 15.1）结构：

| 分区 | 类型 | 内容 | 大小 |
|---|---|---|---|
| disk25s1 | Windows_NTFS | BitLocker 整卷加密（-FVE-FS-），卷标 Ventoy15.1 | 16.3 GB |
| disk25s2 | **0xEF（EFI）** | **FAT16**（mkfs.fat），卷标 VTOYEFI，含 grub/EFI/ventoy 共 1014 个文件 | 33.6 MB |

「检测不到」是**两层原因叠加**：

1. **我们这层**：`ntfs_devices()` 只匹配 `Windows_NTFS` / `Microsoft Basic Data` 两种分区类型，其余静默忽略。
2. **macOS 这层**：diskutil 的分区扫描只对特定分区类型尝试识别文件系统。`0xEF` 分区里的 FAT16 被完全跳过 —— `diskutil` 显示 `no file system`、`diskutil mount` 失败、`mount_msdos` 返回 ENOTSUP（`Operation not supported by device`）。但 `fsck_msdos` 检查**通过**，证明文件系统本身完好。

## 二、方案：裸镜像附加（绝不动分区表）

**绝不能**把分区类型 0xEF 改成 0x0E 来「让 macOS 认」—— UEFI 固件靠 0xEF 定位 EFI 分区，改了 Ventoy 就无法 UEFI 启动。

对策（两层）：

1. **看得到**：新增 `other_devices()` 枚举外置盘上「非 NTFS/BitLocker、未被原生挂载、内容为 FAT 家族」的分区，从 FAT BPB 自己读卷标（macOS 给不出），并入 `list` 输出。
2. **挂得上**：`raw_mount_one()` 把分区内容 `dd` 导出成镜像文件 → `hdiutil attach -readonly -imagekey diskimage-class=CRawDiskImage` 附加。该镜像设备**没有分区表**，macOS 只能按内容识别 → 实测识别为 `MS-DOS FAT16`、自动挂载 `/Volumes/VTOYEFI`。

### 关键细节

- **只读**：镜像挂的是「副本」，写入不会回写原分区。一律 `-readonly`，写入会被 macOS 直接拒绝，不存在「写了却静默丢失」。
- **属主**：镜像 chown 给 GUI 用户后 `su -l <owner> -c "hdiutil attach ..."`，挂载点归属该用户（复用 BitLocker exFAT 分支的成熟模式）。
- **互斥锁**：`raw_mount_one` 持 `lock_mount`；`raw_detach_one` 不取锁（`eject_one` 调它时已持锁，避免自锁死）。
- **卸载/弹出闭环**：`unmount` 分发到 `raw_detach_one`（卸卷 + 摘镜像设备 + 删临时镜像，轮询等设备真正消失再判定成功/告警）；`eject_one` 在弹父盘前先 `raw_detach_parent` 摘掉同盘全部分区镜像，否则磁盘工具里残留「幽灵磁盘」。
- **daemon 不自动挂**：`ntfs-automount.sh` 过滤 `fs` 非 ntfs/bitlocker 的行 —— 否则每个外置盘的 EFI 分区都会被自动挂出来，噪音大。其它分区只由用户显式挂载（菜单 / `ntfsctl mount <dev>`）。
- **裸跑免密**：`resolve_devices` 支持 FAT 卷标匹配；`label_of` 回退到 BPB 读标。

### 验证

- `ntfsctl list --porcelain` → `disk25s2|VTOYEFI|fat16|/Volumes/VTOYEFI|ro|`
- mount → 只读挂载成功，`ls /Volumes/VTOYEFI` 见 EFI/grub/tool 等 1014 个文件
- unmount → 无残留（挂载、镜像设备、临时文件、记录全清）
- 守护进程 12 秒观察：不再自动重挂 VTOYEFI
- 新增 `test/test-other-fs.sh`：**PASS=11 FAIL=0**（自造 64MB FAT16 裸镜像，探测/只读挂载/清理全链路）
- 全量回归：test-manual-lock 13/0、test-automount 7/0、test-boundary 12/0、test-ntfs-rw 14/0、test-bitlocker 17/0

### 过程中的坑

- **bash 多字节坑第三次**：`"$dev）` 的全角括号吞掉变量名 → 输出 `已挂载（??`。规则重申：变量后跟非 ASCII 一律 `${var}`。
- **hdiutil 不接受块设备作镜像输入**：`hdiutil attach /dev/disk25s2` 无效，必须先 dd 成文件。
- **解析 hdiutil 输出**必须 `awk '/^\/dev\/disk/{print $1}' | tail -1` 且核对 ≠ 源设备（曾有误抓源盘的事故）。
- **raw_detach_one 首版误告警**：卸卷后 macOS 常自动摘走无分区表镜像设备，`diskutil eject` 报「无此设备」被当成失败 → 改为轮询等设备消失后再判定。
- **测试脚本用 hdiutil 镜像（非 external）不会进 list**：`other_devices` 只收录外置物理盘，测试断言要区分「镜像测试环境」与「真实盘环境」。

## 三、根除 Touch ID 指纹弹窗

用户反馈测试期间「老是弹出指纹验证」。排查所有提权点：

| 调用点 | 提权方式 | 是否弹窗 |
|---|---|---|
| App `runAdmin` / `listDisks` | `sudo -n ntfsctl ...`（白名单） | 否 |
| 守护进程 | launchd root 直跑 | 否 |
| 我的测试命令 | 全部 `sudo -n`（失败也不弹） | 否 |
| **ntfsctl `as_root()`** | **`sudo "$@"`（无 -n，交互式）** | **是！** |
| install-driver.sh | `osascript ... with administrator privileges` | 是（仅手动点「检查驱动更新」触发） |

根因：`as_root` 是交互式 sudo。macOS 的 sudo 启用了 `pam_tid.so`（Touch ID for sudo），任何非 root 链路碰到它就请求指纹 —— 例如用户在终端裸跑 `ntfsctl mount xxx`（不带 sudo）。

### 修复（两层防御）

1. **`as_root` 改非交互**（`sudo -n`）：免密不可用时**直接失败报错**，绝不转入交互认证。
2. **免密重入**：脚本开头检测「非 root + 运行的是安装版 `/usr/local/bin/ntfsctl`」时，`exec sudo -n "$0" "$@"` 以白名单身份重新调用自身 —— 用户裸跑体验与 root 直跑完全一致：

```bash
if [ "$(id -u)" != "0" ] && [ "${NTFSCTL_REENTERED:-}" != "1" ] && [ "$0" = "/usr/local/bin/ntfsctl" ]; then
  NTFSCTL_REENTERED=1 exec sudo -n "$0" "$@"
fi
```

（sudo 的 env_reset 会清掉 NTFSCTL_REENTERED，但重入后已是 root，不会无限循环。）

### 验证（全程以普通用户 x、无 sudo 前缀）

| 裸跑命令 | 结果 |
|---|---|
| `ntfsctl list` | 成功列出（含 VTOYEFI），零弹窗 |
| `ntfsctl mount disk25s2` | 成功只读挂载（dd/su/hdiutil 全链路免密），零弹窗 |
| `ntfsctl unmount disk25s2` | 成功干净卸载，零弹窗 |
| `sudo -n ntfsctl list --porcelain`（root 路径，App/daemon 用） | 不受影响 |
| test-other-fs.sh 回归 | 11/0 |

> 遗留说明：install-driver.sh 的 `osascript with administrator privileges` 只在用户主动点「检查驱动更新」并真正安装驱动时弹一次，属合理交互，本轮未改。

## 后续可选优化

1. `other_devices` 目前只收 FAT 家族；ext4 等 macOS 本地不认的格式刻意排除。若要支持 ext4 浏览需引入 ext4fuse，另行评估。
2. 镜像导出对大分区（GB 级 FAT32）耗时与磁盘占用线性增长；可按需加「分区大小上限提醒」。
3. install-driver.sh 的管理员授权可改为白名单免密（用户决定）。
