# BitLocker 恢复密码 / .BEK 恢复密钥解锁入口（2026-10-14 21:45）

> 版本：0.0.9 ｜ 模型：DeepSeek-V4.1-Flash ｜ 仓库：https://github.com/pixian5/ntfsformac

## 目标

在原有「用用户密码解锁 BitLocker」之上，补齐另外两种标准解锁方式：

1. **48 位恢复密码**（recovery password）——Windows 里最容易拿到的凭据（BitLocker 恢复密钥页面 / Microsoft 账户）；
2. **.BEK 恢复密钥文件**——由 Windows「导出恢复密钥」产生的文件。

同时让菜单栏 App 对这两种方式也有图形入口，并支持「记住 + 下次插入自动解锁」。

## 改动

### 1. ntfsctl：新增恢复密码参数

`unlock` 子命令新增 `--recovery <48位>` 与 `--recovery-file <路径>`：

```bash
ntfsctl unlock disk4s1 --password-file /path/pw      # 用户密码
ntfsctl unlock disk4s1 --recovery 123456-…-123456    # 48 位恢复密码（连字符可省略）
ntfsctl unlock disk4s1 --recovery-file /path/rec     # 从文件读恢复密码
ntfsctl unlock disk4s1 --bek /path/XXXX.BEK          # BEK 恢复密钥文件
ntfsctl unlock disk4s1 --clearkey                     # 明文保护的卷
```

**关键坑：dislocker 对恢复密码的格式要求极严。**
dislocker 源码 `src/accesses/rp/recovery_password.c` 的 `is_valid_key()` 里有一句硬校验：

```c
if(strlen((char*)recovery_password) != 48+7)   /* 必须是 55 字符 */
```

它按「每 6 位数字 + 1 个连字符」分组解析（`rp += 7` 逐块前进），所以**必须传 55 字符的带连字符形式**，
既不能只传 48 位纯数字，也不能带多余空格。ntfsctl 因此做了规范化：
先 `tr -cd '0-9'` 只留数字 → 校验恰好 48 位 → `sed` 按 6 位一组重新插入连字符 → 才交给 `dislocker -p`。

用户从 Windows 复制来的恢复密码无论带不带连字符，都能直接粘进去用。

### 2. App：三种解锁入口 + 方法感知的凭据记忆

- 菜单栏对未解锁的加密卷列出三项：**用密码解锁… / 用恢复密码解锁… / 用 .BEK 文件解锁…**；
- 恢复密码弹窗用等宽字体、带「记住恢复密码」勾选；BEK 用 `NSOpenPanel` 选文件；
- 钥匙串记忆格式升级为 `<凭据>\n<方法码>`（`u`=用户密码 / `r`=恢复密码 / `b`=BEK 路径），
  方法码放末尾，因此凭据里含冒号或换行也不会被误解析；旧版本存的纯密码按 `u` 兼容处理；
- 自动解锁按记忆的方法选择正确参数（恢复密码 → `--recovery-file`；BEK → `--bek`），
  记住的 BEK 文件若已被移走则跳过并清除，不会反复失败提示。

## 验证方法与结果

### 恢复密码格式链路（用真实加密 U 盘 disk4s1，密钥故意填错）

| 输入 | 期望 | 实测 |
|---|---|---|
| 48 位纯数字（无连字符） | 能通过格式校验、走到密钥计算才失败 | ✅ dislocker 不再报 `Wrong length (has to be 55)`，而是 `Unable to compute regions`（格式正确、密钥错误） |
| `12345`（位数不足） | 被 ntfsctl 本地校验拦住 | ✅ `恢复密码应为 48 位数字…，当前 5 位` |
| 伪 `.BEK` 文件 | 走到解析才失败，而非参数错误 | ✅ `Unable to compute regions` |

失败后 **无容器目录 / 无互斥锁 / 无 dislocker-fuse 进程 / 无容器挂载** 残留；`list` 仍为 `bitlocker||locked`。

### UI 渲染链路

真实 U 盘 `ntfsctl list --porcelain` 输出 `disk4s1|BitLocker-disk4s1|bitlocker||locked`（正好 5 段），
App 的 `listDisks()` 用 `split(separator:"|", omittingEmptySubsequences:false)` 取 f[2]=fs、f[4]=state，
且不丢弃 bitlocker 盘 → 三个解锁入口会正常列出。二进制中已确认三个菜单标题字面量存在。

### 回归

`test/test-bitlocker.sh` 自检 **17 项全绿**（组件、签名检测、不自动挂载、错误凭据资源清理）。

真实 U 盘上**成功解锁**这一步尚未执行——需要该盘的真实密码 / 恢复密码 / .BEK 文件。

## 附带发现

- **Swift 小字符串优化会影响"二进制字符串校验"**：≤15 字节的 UTF-8 字面量被内联存储，
  不在 `__TEXT,__cstring` 里，用 `strings`/`grep` 找不到。
  例：`用密码解锁…`(18 字节) 能找到，而 `--bek`(5 字节)、`已忘记凭据`(15 字节) 找不到。
  校验时应用 Python 逐字节 `count()`，且要意识到"找不到 ≠ 没编进去"。
